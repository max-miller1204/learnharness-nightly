# Subscription search

The owner approved the independent search backend in the existing **Settings → Agent → Tools → Search engine** picker on November 18, 2026. [Approved proposal and provider research](t3-thread://v2/7b5ba43d-a4e4-4388-a505-3d60b101c0fc/thread:delegated-task:command%3Amcp%3A30fe5f5e-a7f9-4dd2-8ee0-492f174f3764%3Adelegate-task%3Aresearch-learnharness-web-search-1)

- Offer eligible signed-in subscriptions alongside Tavily, Brave, Exa, Firecrawl, and Ollama. Show the provider and account identity, and disclose that search can consume plan allowance or credits. Selecting a subscription opts in that account for every LearnHarness-managed web search, independently of chat and researcher models. The picker requires neither a researcher model selection nor a search key.
- Automatic considers only configured keyed engines. Honor existing background-use consent. Bind an explicit subscription selection to the selected connection and require reselection after an account change. A failed search must never switch accounts, engines, keys, or billing routes.
- Send the search query to the selected backend and preserve the provider’s source URLs as clickable citations. Report actionable reasons for unsupported routes, disconnects, policy denials, and usage limits. Keep known-URL fetching available.

## Rollout and evidence

1. **ChatGPT OAuth.** Use the existing Sign in with ChatGPT account lease and the public Responses API. The OAuth route documents hosted web search subject to model and workspace policy. In an isolated LearnHarness instance with an approved account, verify native search completion, source links, usage attributed to that account by the provider, and failure without fallback. [OAuth requirements](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) · [Account models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) · [Search citations](https://developers.openai.com/api/docs/guides/tools-web-search) · [Plan usage](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)
2. **Claude Code.** Proceed after the ChatGPT proof and confirmation that LearnHarness’s distribution meets Anthropic’s product integration terms. Use the user’s own subscription login in the unmodified CLI. Prove effective authentication and account identity, native headless search with cited sources, the exact effective tool list, and failure without fallback. Anthropic documents separate tool and permission flags and an `EndConversation` exception to the tool restriction. [Integration terms](https://code.claude.com/docs/en/legal-and-compliance) · [CLI reference](https://code.claude.com/docs/en/cli-reference) · [Headless search](https://code.claude.com/docs/en/tools-reference#session-search-limit) · [Plan usage](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
3. **Grok OAuth and GitHub Copilot.** Show both as unavailable. Grok’s documented search uses an API key and its documented subscription integrations do not establish search eligibility on LearnHarness’s OAuth route. GitHub documents web tools on its Copilot runtime, while LearnHarness uses a direct model adapter. Each shipped route requires its own provider-supported proof. Adding a runtime, reviving a parked CLI, or using a private endpoint or API key substitute is outside this approval. [Grok subscriptions](https://x.ai/news/grok-opencode) · [Grok search](https://docs.x.ai/developers/tools/web-search) · [Copilot CLI tools](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/allowing-tools) · [Copilot SDK authentication](https://docs.github.com/en/copilot/how-tos/copilot-sdk/setup/github-oauth)

Live proof uses an isolated app and approved account, with sign-in through the provider’s own flow. Fixture tests establish app behavior. Provider usage and eligibility require live evidence.

ChatGPT search selects one model before dispatch from the connected account’s catalog. It prefers the most efficient documented Responses web-search models, starting with GPT-6 Luna and GPT-5.6 Luna. The priority uses published standard output-token rates as an efficiency proxy. Each eligible model must support low reasoning. A failed search is reported without another model attempt.
