# Subscription search

The owner approved the independent search backend in the existing **Settings → Agent → Tools → Search engine** picker on November 18, 2026. [Approved proposal and provider research](t3-thread://v2/7b5ba43d-a4e4-4388-a505-3d60b101c0fc/thread:delegated-task:command%3Amcp%3A30fe5f5e-a7f9-4dd2-8ee0-492f174f3764%3Adelegate-task%3Aresearch-learnharness-web-search-1)

- Offer eligible signed-in subscriptions alongside Tavily, Brave, Exa, Firecrawl, and Ollama. Show the provider and account identity, and disclose that search can consume plan allowance or credits. Selecting a subscription opts in that account for every LearnHarness-managed web search, independently of chat and researcher models. The picker requires neither a researcher model selection nor a search key.
- Automatic considers only configured keyed engines. Honor existing background-use consent. Bind an explicit subscription selection to the selected connection and require reselection after an account change. A failed search must never switch accounts, engines, keys, or billing routes.
- Send the search query to the selected backend and preserve the provider’s source URLs as clickable citations. Report actionable reasons for unsupported routes, disconnects, policy denials, and usage limits. Keep known-URL fetching available.

## Rollout and evidence

1. **ChatGPT OAuth.** Use the existing Sign in with ChatGPT account lease and the public Responses API. The OAuth route documents hosted web search subject to model and workspace policy. In an isolated LearnHarness instance with an approved account, verify native search completion, source links, usage attributed to that account by the provider, and failure without fallback. [OAuth requirements](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) · [Account models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) · [Search citations](https://developers.openai.com/api/docs/guides/tools-web-search) · [Plan usage](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)
2. **Claude Code.** Proceed when the ChatGPT live proof passes. On November 18, 2026, the owner confirmed that LearnHarness’s distribution meets Anthropic’s product integration terms for this route. LearnHarness runs the user’s installed, unmodified CLI and leaves all its authentication methods intact. The user signs in through Anthropic’s own terminal flow. LearnHarness does not collect or store Claude credentials, pay for usage, or intermediate billing. Search uses a separate headless `claude -p` invocation with only `WebSearch` enabled. Chat runs continue to use `--tools ""`. Show plan usage in the picker. Prove the subscription authentication and account identity, native headless search with clickable source titles and URLs, the exact effective tool list including any documented CLI exception, and failure without fallback. Anthropic documents a per-turn headless search limit and an `EndConversation` exception to the tool restriction.

   Implementation (owner decisions, November 18, 2026): the account comes from `claude auth status --json`, which reports the CLI's own sign-in without credentials. The picker label is `email · Claude <plan>`, or `Claude Code account · <sign-in method>` without an email. `auth status` runs from an empty private temporary directory with the search's environment, so project settings in a shared directory cannot change the reported sign-in. The selection is bound to a hash of the email, organization, sign-in method and API provider, so another account requires reselection. A sign-in other than a Claude plan reports no account identity, so the hash also covers a one-way fingerprint of the credentials LearnHarness can see in the CLI's environment and user settings `env`: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `AWS_PROFILE`, `AWS_ACCESS_KEY_ID`, `AWS_BEARER_TOKEN_BEDROCK`, `ANTHROPIC_VERTEX_PROJECT_ID`, `GOOGLE_APPLICATION_CREDENTIALS`, plus the `apiKeyHelper` command text. The fingerprint is computed in memory and is never stored, logged or shown. LearnHarness never runs the apiKeyHelper or calls a cloud provider with the user's credentials. Accepted limit (owner decision): a switch behind the same helper command, AWS profile or Google login, or a Console key the CLI stores itself, goes unnoticed. Keys stored in LearnHarness never reach the CLI. Any sign-in method is allowed: a plan sign-in discloses plan usage limits, and any other method discloses that search may be billed to that account. The Providers → External CLI → Claude Code opt-in is required. Each search runs the `haiku` alias at low effort with `--tools WebSearch --allowedTools WebSearch`, a strict empty MCP config, and the chat run's isolation flags. The query is sent on stdin, from an empty temporary directory, with a 60 second limit. A search stops if the CLI's start-up tool list holds anything besides `WebSearch` and `EndConversation`. On POSIX the CLI runs in its own process group, and a timeout or abort kills the whole group before its directory is removed. Hits are the native WebSearch result titles and URLs, without snippets. The account is checked again after the run, and a changed account discards the result. 3. **Grok OAuth.** On November 18, 2026, the owner approved one isolated live probe after the ChatGPT and Claude Code proofs. Use the owner’s sign-in through the existing Pi xAI OAuth connection to the public Responses endpoint at `https://api.x.ai/v1/responses`. xAI documents the hosted `web_search` tool on that endpoint with API-key examples. The probe must use OAuth and record whether native search completes, whether the provider returns source citations, and what xAI reports for subscription usage or any extra charge. If the probe establishes subscription search, offer Grok in the picker with explicit account binding and usage disclosure. Reuse Responses citation extraction and use one fixed model per call. If xAI refuses, keep the option unavailable and show the provider’s actual reason. The live probe passed: native search completed through the owner's Grok OAuth sign-in on grok-4.7 at low effort and returned 3 citations. xAI reported 34,602 tokens and a request cost of $0.04806896 for that one grok-4.7 low search (November 18, 2026, at 99107a6). Account-level billing or allowance changes were not observable. Grok is therefore selectable whenever a Grok account is connected (owner decision), with no extra cost warning beyond the usage disclosure. It uses the native subscription lease with background use consent, adds the hosted `web_search` tool with `tool_choice: required`, uses grok-4.7 at low reasoning effort and fails with a clear reason, trying no other Grok model, when the connection catalog does not offer it, labels the account "Grok account" bound to its connection, and appends xAI's own error text to a failure. Live proof uses an isolated app and approved account, with sign-in through the provider’s own flow. Fixture tests establish app behavior. Provider usage and eligibility require live evidence.

ChatGPT search selects one model before dispatch from the connected account’s catalog. It prefers the most efficient documented Responses web-search models, starting with GPT-6 Luna and GPT-5.6 Luna. The priority uses published standard output-token rates as an efficiency proxy. Each eligible model must support low reasoning. A failed search is reported without another model attempt. [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) · [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) · [Model selection](https://developers.openai.com/api/docs/guides/model-selection)

Search models are fixed, with no user setting (owner decision, November 18, 2026): each provider uses its latest small model at low reasoning. ChatGPT prefers `gpt-6-luna` as above. Claude Code passes the CLI's `haiku` alias so it keeps tracking the latest Haiku. In CLI 2.1.327 the alias resolves to Haiku 5.5 (`claude-haiku-5-5`) for Claude plan and Anthropic API sign-ins, and to Haiku 4.5 on Bedrock, Vertex, Foundry and the other cloud routes, which the owner accepted. Grok uses `grok-4.7`; Pi's xAI catalog maps its low thinking level to the Responses `reasoning.effort` value `low`.
