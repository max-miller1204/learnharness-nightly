## Connections and teaching

- The app talks to one LearnHarness server at a time over Tailscale Serve HTTPS. A learner can save multiple origins, switch servers, and explicitly choose which server opens on cold launch. When the default cannot be reached, the app shows Retry and the server picker. Each bearer lives in SecureStore under its own normalized origin, including the port. A revoked credential is cleared and that server can be paired again.
- Scan the same QR shown by `lh pair` and Settings → Devices with `expo-camera`. Request camera permission when the learner chooses Scan. Show the decoded HTTPS destination and wait for Connect. Paste the pairing link or type the HTTPS origin and one-time code as fallbacks.
- Read the public server descriptor before pairing and on connect or reconnect. Use exact protocol 1. Send the version header, display the protocol's client-too-old and server-too-old messages, and handle a later 426. Against a server without either optional capability, ordinary pairing, teaching, and the main practice loop still work.
- List, create, and resume teaching sessions. Send text, answer built-in questions, see teacher replies live, stop a turn, and retry a failed reply. Render settled text and existing session image snapshots. The server's record is the authority after a send, stream settlement, foreground, or reconnect. Use both SSE routes and detach and invalidate old streams on a server change. When a write's response is lost, reconcile with the record before offering a fresh send. Protocol 1 has no client write idempotency key.
- Provider setup and other genuinely web-only interactions use the browser. The full graph and folder browser, side questions, mid-turn steering, and dictation are deferred. Push notifications and OTA updates are outside beta 1. Photos and individual files upload as in follow-up 2 below. Folder uploads follow in a later mobile PR.

## Practice and optional capabilities

Start from a topic, bring a problem, or resume a session. Create with `POST /api/chats` and `{kind:"practice"}`, then send text through `POST /api/chat`. Render the saved statement with Markdown and math. Repeated `{type:"thinking", problemCallId, text}` submissions target the current problem. Reveal the posed problem's committed solution only after the saved successful `conclude` and hide it for a discarded problem. Offer follow-up text and explicit `{type:"next"}` between problems while idle. Use the same Stop, reconnect and retry paths as teaching. Plugin exercises and plugin questions can display their saved prompt and use browser handoff for the web editor.

| Capability | Contract |
| --- | --- |
| `practice-controls-v1` | `GET /api/practice/propositions` returns `{propositions: GraphContextPick[]}` to populate a searchable multi-picker. Follow the web picker's source visibility, including shared premises of visible chains. Pass picks as `graphContext.propositions` at create time, for teaching and practice sessions alike (follow-up 1). `POST /api/chats/:id/dismiss` takes `{input:{type:"dismiss-problem",problemCallId}}` and returns `200 {ok:true}` when saved or `202 {ok:true,parked:true}` when queued for the active turn to settle. The discard itself starts no turn. The deferred conclusion rides the next input. Hide graph picking and Discard when the capability is absent. |
| `browser-handoff-v1` | **Open in browser** goes to the exact session on the active origin and uses the browser cookie or existing manual pairing prompt. **Pair phone browser** uses authenticated `POST /api/auth/pairing-token` and opens `/pair#token=…&chat=…` at that same origin. The browser strips the fragment immediately, checks its own cookie, and spends the code only if signed out. The target is constructed locally from the session ID alone. The native bearer stays in the native app. A returning browser adds no device entry and a first-time browser adds one. Hide assisted browser pairing when the capability is absent. |
| `lesson-view-v1` | `GET /api/jobs?chatId=…` returns `{jobs: JobRecord[], turnInFlight}`: the session's background helpers with live status. Read it on open, on reconnect, and (debounced) on each `jobs-changed` event for the chat or with no chatId. A helper that stops running re-reads the record. `POST /api/chats/:id/dismiss` also takes `{input:{type:"dismiss",toolCallId,answer}}` to skip a built-in question, with the practice discard's 200/202 answers. The skip starts no turn. A mid-turn skip is answered `202 {ok:true,parked:true}`, and the phone then stops the turn. The server applies the parked skip when that turn settles, against the saved record. If the question is no longer pending by then (for example, input from another client answered or superseded it), the server drops the skip and saves nothing, as it does for the browser. The phone shows no error for a dropped skip. Hide live helper status and Skip when the capability is absent. |

## Package and release

`apps/mobile` is an independent Expo npm project with its own lockfile, TypeScript, ESLint, Metro and EAS configuration. It imports the shared protocol and portable core source. React and React Native resolve from the mobile installation; the root Next app excludes mobile files from its typecheck and lint. Required CI **Check** includes an isolated mobile install, Expo dependency checks, lint, typecheck, tests, and iOS and Android bundle exports for mobile, shared-source and CI changes.

Both stores display **LearnHarness Nightly**. The iOS bundle ID and the Android package are both `com.maxmiller.learnharness.nightly`, under the owner's namespace rather than upstream's `com.learnharness`. EAS builds store binaries for TestFlight and Play internal testing. Beta updates are fresh signed binaries. The owner designates accounts, testers and a tailnet test server before signing and submission. See the [mobile release runbook](../../apps/mobile/README.md).

## Full lesson view (follow-up 1)

Approved by the owner on 2026-11-18. The session view shows what the web transcript shows for plans, research and checks, as native screens.

- **Teacher's reasoning.** A collapsed "Agent's thinking" row per thinking block. Only the learner opens it. While the live turn is thinking, the row reads "Thinking…".
- **Phases, plan and compaction.** The top bar names the phase (Probing, Planning, Teaching) as it names Practice. Dotted Planning and Teaching seams sit where the web draws them. "Context compacted" and the "History compacted · Nk tok" cut follow the record and can't be tapped. The plan renders where the teacher made it, as the web's diagram drawn with react-native-svg from the shared layout in `src/core/plan-layout.ts`. Tapping it, or **View plan** in the top bar's **Session options** (…) menu, opens the full-screen live plan: statuses derive from the checks, the current node glows, pinch zooms, drag pans and the fit is the floor.
- **Helpers.** Research, PDF, demo, figure and plugin dispatches show a live card (spinner, elapsed seconds, latest activity) and then a ✓ or ✗ line. Delivered research and PDF briefs open on tap. Plugin results show their text. Demo and figure results point to the browser until follow-up 5. Delivery steers never render as the learner's words.
- **Teach checks.** A teach-phase check (not a prediction) waits behind **Check your understanding**, with a **Thinking while reading** field that rides the answer or the skip as `readingThinking`. A check that directly follows another question arrives open. Answered cards show the learner's thinking rows. **Skip** asks first: "Skip this question? The teacher moves on without it."
- **Graph picks for teaching.** New session offers the graph picker for teaching too. The session shows the web's folded Graph context card.

## Attach photos and files (follow-up 2)

Approved by the owner on 2026-11-18. The phone attaches through the web's `attachment-uploads-v1` contract (see [remote-safe attachments](remote-safe-attachments.md)) with its paired bearer. No server change.

- **Paperclip.** New session and the session composer show a paperclip left of the text box when the server offers `attachment-uploads-v1`. It is dimmed while a reply runs and hidden on practice thinking, which the server never accepts uploads for. Its menu offers **Take photo** (the camera), **Photo library** (several photos) and **Files** (the system file picker, several files of any type).
- **Draft chips.** Each pick shows as a chip with its name and progress. Upload starts at pick. A failure shows its error with **Retry** and **Remove**; Remove releases the reservation. Picks over the shared limits (100 files per message, 10 MiB per image, 80 MiB of images, 50 MiB per other file) are refused before upload with the web's messages.
- **Sending.** A message with files needs text. With files and no text, Send is dimmed and "Add a message to send these files." shows. Send waits for running uploads, and the text and Remove stay locked meanwhile. The same message and files reuse one send ID, so a retried send never duplicates. A new session with files opens through `POST /api/attachments/start`. Saved messages show their files as chips, with "File unavailable. Attach it again to use it." for a missing one.
- **Photos.** Photos are JPEG at 80% quality. iOS returns its compatible representation, so HEIC becomes JPEG. Camera photos and Android library photos, whose names are internal IDs, are named `photo-YYYYMMDD-HHMMSS.jpg`, with `-2`, `-3` for more in one pick (owner, 2026-11-18). iPhone library photos keep their names. Files picks keep their display names; on Android the app copies a content pick into its cache to read it, and refuses one over 50 MiB before copying with "A picked file exceeds the 50 MiB per-file limit." The app deletes its copies when a file is sent, removed or refused, or the composer closes. A photo's type and extension follow the bytes written, since Android re-encodes HEIC, GIF and WebP library photos as JPEG. On both platforms the app removes location data (GPS EXIF, XMP and IPTC) from photo JPEGs before upload and keeps orientation (owner, 2026-11-19). The phone doesn't resize; the server shrinks images for the model.
- **Permissions.** iOS camera: "Allow LearnHarness Nightly to use the camera to scan pairing QR codes and take photos you send." iOS photos: "Allow LearnHarness Nightly to access your photos so you can send them to your sessions." Android uses the existing camera permission and the system photo picker. Neither platform requests the microphone. A refused camera shows "Camera access is off. Allow it for LearnHarness Nightly in Settings to take photos." and keeps the draft.
- **Native modules.** `expo-image-picker` and `expo-file-system` (picker and `UploadTask` PUT) need a new app build.
